A2L-Forge · Visual Upgrade Prototype

v6.0 proposal — interactive preview, no app code touched

1 · App Shell & Chrome

Titlebar, menu bar, activity bar, status bar. The prototype fixes the three competing accent blues (#007acc / #3794ff / #0e639c) to one token-driven accent per variant, and lifts contrast on inactive icons.

  1. One accent. Titlebar logo, activity indicator, buttons and status bar all use the single --accent token (A/C: blue family, B: teal→blue).
  2. Contrast fix. Inactive activity-bar icons go from ~2.9:1 (40% white) to ≥4.5:1 muted tone; active state gets an accent pill/edge.
  3. Radius & density tokens. Each variant ships a consistent radius/padding scale instead of ad-hoc values (B is softest, C is densest).
  4. Status bar. Uses the same accent as the rest of the UI; error state stays red but with accessible text.

2 · Explorer Tree

Entity tree with kind colors preserved. Selection becomes an accent-tinted rounded row with an edge marker (instead of hardcoded #37373d !important); search field shows the proposed focus ring.

3 · Entity Detail View

Properties grid with section headers. Muted grays (#666/#777) are replaced by accessible tones, section headers get a small accent tick, zebra rows get slightly more visible separation in variants.

4 · Create Entity Dialog

The entity-type selector moves out of the dialog title into a segmented picker in the body (current UX puts it inside DialogTitle). Inputs show the unified focus treatment. Try tabbing through fields.

5 · ELF Symbol Table

Struct parent/member rows, checkboxes, sortable headers. Sortable column headers become keyboard-operable buttons with visible focus (Tab to them), and the active sort gets an accent arrow chip.

6 · Feedback: Banners, Toasts & Focus States

ELF-change notification banner, error status, and keyboard focus visibility. The dismiss “×” becomes a real focusable control.
